# 13. Ошибки пилотов становятся постоянными тестами

Каждый подтверждённый промах на пилоте — ложная тревога, пропуск, неизвестность,
которую данные не оправдывали, — должен улучшать следующую версию и оставаться
исправленным. Последовательность фиксирована, и каждый шаг что-то оставляет в
репозитории:

| Шаг | Что | Куда попадает |
|---|---|---|
| 1. **ошибка** | Находка, которую видел клиент и которую ручная перепроверка подтвердила как неверную: ложная тревога (`false-alarm`), неуказанная проблема (`miss`) или `unknown` там, где данных хватало (`unjustified-unknown`). Время перепроверки записывается | `case.yaml`: `kind`, `found: pilot`, `summary`, `recheck_minutes` |
| 2. **причина** | Почему CLI ошибся, одним абзацем — правило, коллектор или допущение | `case.yaml`: `cause` |
| 3. **сценарий** | Ситуация, воспроизведённая на **искусственных данных**: план и то, что показал хост, в формах `audit.manifest`, `audit.capabilities` (и `audit.plan`) самого отчёта, переписанные вручную | `input.json` |
| 4. **ожидаемый результат** | Итог, к которому должно прийти каждое затронутое правило | `case.yaml`: `expect.rules` (и `no_blocker`, `no_blocker_for`, `changes_contain`) |
| 5. **исправление** | Изменение CLI. До него случай падает, после — проходит; сначала убедитесь, что он падает | код, `fixed_in` |
| 6. **постоянный тест** | Случай выполняется в каждом `make test` (`TestPilotRegressions`), то есть перед каждым релизом; если ситуацию можно поставить в Docker — ещё и сценарий стенда с `regression: <задача>`, на котором блокирует [шлюз выпуска](12-quality-and-release.md#шлюз-выпуска) | `app/witness/testdata/regressions/<задача>-<слаг>/`, `bench/scenarios/…` |

```bash
make regression NAME=DW-123-short-slug   # копирует шаблон, заполняет id и task
make test                                # новый случай должен падать, пока нет исправления
```

Упавший случай называет себя, свой вид и задачу и то, что вернулось:
`DW-83-hand-made-external-network (false-alarm, DW-83): witness.network_name_conflict
ended "manual-check", want "no-problem" — the defect is back: …`.
`go test -v -run PilotRegressions ./app/witness` печатает ещё и число случаев и
записанное в них время ручной перепроверки — цену, которую заплатили пилоты,
хранящуюся рядом с исправлением.

## Что никогда не попадает в архив

Случаи искусственные намеренно. Из отчёта клиента не копируется ничего: ни файл
отчёта, ни имя хоста, ни публичный адрес, ни домен, ни ID движка или машины, ни
секрет. `TestRegressionArchiveHoldsNoClientData` отвергает случай, в котором есть

- что-либо, что маскирует проверка учётных данных (`app/redact`);
- публичный IP-адрес — проходят только loopback, RFC 1918, link-local и
  документационные диапазоны (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`,
  `2001:db8::/32`);
- домен вне зарезервированных имён (`*.example`, `example.com/.net/.org`, `*.test`,
  `*.invalid`, `*.localhost`);
- адрес e-mail вне них;
- 32- или 64-значный шестнадцатеричный ID или UUID — движка, машины или образа, —
  если он не начинается с `00000000`.

Сама проверка тоже протестирована (`TestClientDataLint`) на каждом виде.

## Архив сейчас

Семь случаев — по исправленным на сегодня дефектам; ни один пока не пришёл с пилота,
поэтому у них `recheck_minutes` равно `0`, а `found` — `review` или `bench`:

| Случай | Вид | Дефект |
|---|---|---|
| `DW-24-port-number-only` | ложная тревога | порты сравнивались по номеру: 53/tcp блокировался 53/udp |
| `DW-52-foreign-container-replaced` | пропуск | список изменений «заменял» контейнер другого проекта |
| `DW-79-snapshot-called-missing` | ложная тревога | непроверяемый снапшот выдавался отсутствующим |
| `DW-80-unreachable-engine-external-volume` | ложная тревога | «внешнего тома нет» по движку, который не ответил |
| `DW-81-project-name-flag` | ложная тревога | деплой с `--project-name` считал свой контейнер чужим |
| `DW-83-hand-made-external-network` | ложная тревога | внешняя сеть, созданная вручную, считалась общей с другим стеком |
| `DW-87-hand-made-external-volume` | ложная тревога | внешний том, созданный вручную, считался чужими данными |

Семь сценариев стенда несут те же задачи в `regression:` (DW-24, DW-52, DW-80, DW-81,
дважды DW-83, DW-87), поэтому шлюз блокирует релиз и при их возврате в Docker.
